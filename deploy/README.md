# Инфраструктура

```
Браузер ────────────► abcofme.ru (Москва, Caddy выбирает путь по IP)
                      ├─ Россия: 302 → my.abcofme.ru ────────────────────┐
                      └─ остальные: 302 → app.abcofme.ru → NL: TLS ───────┴─► сервер в Москве
Telegram Mini App ──► app.abcofme.ru → NL: TLS ────────────────────────────► сервер в Москве
                   web (Caddy): TLS, HTTP/1.1+2, сжатие, статика, /api → api
                   api (FastAPI) · bot (aiogram + планировщик) · db (Postgres 17) · redis
                   stt — распознавание речи для диктовки в дневнике (stt/app.py), ходит к нему только api
                   bot ──► ретранслятор в NL ──► api.telegram.org
```

- **Москва** — всё, что видит пользователь, и все данные. Снаружи открыты только 22, 80, 443.
- **NL** — один nginx на 443 с разбором по SNI (`relay/nginx-stream.conf`, нужен `libnginx-mod-stream`):
  - `abcofme.ru`, `www.`, `app.` — пересылка TCP в Москву как есть. TLS не расшифровывается, сертификаты
    выпускает Caddy в Москве (80-й порт тоже пересылается). Зачем: из РФ режут ответы московского сервера
    на адреса многих VPN, и у пользователей Telegram через VPN мини-апп падал с ERR_TIMED_OUT.
    `app.` — конечный адрес приложения для зарубежного пути.
  - без SNI — ретранслятор Bot API (`relay/nginx-tg-relay.conf`, слушает `127.0.0.1:8443`): из российских ДЦ
    `api.telegram.org` недоступен. Пускает только IP московского сервера (`geo` в stream),
    сертификат самоподписанный, бот проверяет именно его. Ретранслятор проверяет сертификат
    `api.telegram.org` по системным CA. Логи HTTP-запросов отключены, поскольку URL содержит токен бота.
  - мониторинг: раз в минуту проверяет `/api/health` и шлёт алерт в Telegram.
  - `relay/nginx-restart.conf` устанавливается как `/etc/systemd/system/nginx.service.d/restart.conf`:
    systemd повторяет запуск nginx через 10 секунд при ошибке. Это нужно, если после загрузки ОС
    DNS ещё не отвечает и `api.telegram.org` не разрешается при проверке конфигурации nginx.

  Адрес NL и сертификат ретранслятора в репозиторий не кладём (`.env`, `/etc/theabc/relay-ca.pem`).
  `TRUSTED_RELAY_IP` в серверном `.env` задаёт адрес NL для приёма PROXY protocol в Caddy.
  Перед первым включением `proxy_protocol on` в nginx обновите Caddy и его окружение.
  Затем одновременно загрузите `nginx-stream.conf` и `nginx-tg-relay.conf`, проверьте `nginx -t`
  и перезагрузите nginx. Так API получает настоящий адрес клиента для ограничения попыток входа.
- **Браузер и мини-апп** (`diary/src/utils/api.js`): страница, API, потоковые ответы и аватарки
  используют один origin. Проб скорости и переключений на `my.` в клиенте нет: они могли
  переопределить выбор по стране. На конечных поддоменах повторного выбора пути нет.

## Маршрутизация по стране IP

Используются существующие Москва и NL, обычный DNS Timeweb и HTTP-редиректы. Главная страница
`abcofme.ru/` принимает GET/HEAD в Москве: Caddy проверяет реальный IP соединения, российским
адресам отвечает временным 302 на `my.`, остальным и неизвестным — на `app.`. Параметры
query string сохраняются, fragment наследуется браузером согласно HTTP. Ответ не кэшируется.
API, вебхуки, статика и POST-запросы не перенаправляются.

| Имя | Тип | Значение DNS |
| --- | --- | --- |
| `abcofme.ru` | A | `5.129.200.77` (Москва) |
| `www.abcofme.ru` | CNAME | `abcofme.ru.` |
| `my.abcofme.ru` | A | `5.129.200.77` |
| `app.abcofme.ru` | A | IP ретранслятора в NL из серверного `.env` |
| `direct.abcofme.ru` | A | `5.129.200.77` (совместимость со старыми ссылками) |

`www.` сначала переходит на основной домен. Для ручного обхода выбора пути можно открыть
нужный поддомен сразу. Оба конечных адреса обслуживают тот же backend и ту же базу данных.
Браузерные cookie остаются привязанными к хосту: при первом переходе на другой поддомен
нужно войти заново; сохранённые пользовательские данные остаются в общей БД.

Важное ограничение: всем посетителям нужно сначала получить короткий ответ от Москвы. Если
зарубежный IP не может установить с ней соединение, редирект получить невозможно — такому
посетителю нужна прямая ссылка `https://app.abcofme.ru/`. Перенаправление не заменяет GeoDNS
на уровне первого TCP-соединения и не устраняет недоступность самого NL.

Порядок включения: сначала развернуть конфигурацию, проверить оба поддомена и сертификаты,
затем изменить DNS по таблице и дождаться обновления кэшей (текущий TTL — 600 секунд).
NS менять не нужно. При замене A-записей проверить также AAAA/HTTPS/SVCB, если они есть.

Старый `direct.` остаётся совместимым конечным адресом без дополнительного редиректа.

### Telegram Mini App

`WEB_APP_URL=https://abcofme.ru/` остаётся адресом сайта. Для кнопок мини-приложения задаётся
отдельный `TELEGRAM_WEB_APP_URL=https://app.abcofme.ru/`: меню бота, новые сообщения и
уведомления открывают конечный адрес без смены домена. При запуске бот синхронизирует
своё меню через `setChatMenuButton`, если отдельный URL задан.

Главное мини-приложение в профиле бота настраивается отдельно в BotFather:
`/mybots` → `@abcofmebot` → Bot Settings → Configure Mini App → URL
`https://app.abcofme.ru/`. Bot API не меняет этот URL. Кнопки в старых сообщениях сохраняют
прежнюю ссылку — после изменения нужно открыть мини-приложение из обновлённого меню.

В Telegram используется путь через NL для всех IP. Выбор страны через HTTP-редирект остаётся
у обычного сайта. В iOS доверенный origin привязан к исходному URL запуска: после перехода
на другой домен клиент может не передавать команды SDK, включая `expand` и `requestFullscreen`.
Сохранение `initData` в fragment при редиректе не гарантирует работоспособность этого моста.
Для прямого входа в мини-приложение можно отдельно настроить WebApp-кнопку на `my.`;
между конечными доменами внутри WebView переходить не следует.

### Локальная база стран

`geo/ru-ips.caddy` — российские IPv4/IPv6-сети из [DB-IP Country Lite](https://db-ip.com/db/download/ip-to-country-lite),
производные данные под [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Релиз и SHA-256
исходного архива записаны в заголовке. Атрибуция DB-IP также включена в тело страницы редиректа.
При посещении сайта внешних запросов геолокации нет. Lite-база не гарантирует точную страну
каждого адреса; VPN определяется по своему выходному IP.

DB-IP публикует обновления ежемесячно. Скачать CSV-архив нужного месяца с официальной страницы,
затем обновить список и выложить обычным деплоем:

```bash
python3 deploy/geo/update_ru_ips.py /путь/dbip-country-lite-ГГГГ-ММ.csv.gz --release ГГГГ-ММ
python3 -m unittest backend.tests.test_geo_routing
```

Автодеплой перезагружает Caddy при изменениях и основного Caddyfile, и каталога `deploy/geo/`.
Откат редиректов — убрать `import geo_entry` из блока сайта. Вход тогда открывает приложение
непосредственно на основном домене по его текущему DNS-маршруту.

## Деплой

Автоматический: `theabc-autodeploy.timer` раз в минуту делает `git fetch` и при новом коммите в `main`
собирает Compose, ждёт готовности сервисов и перезагружает Caddy при изменении его конфигурации.
Упавший коммит повторно не собирается автоматически.

Обновление локальной копии Telegram WebApp SDK открывает PR. В настройках GitHub Actions разрешите
создание PR, а в открытом PR одобрите запуск проверок. До слияния проверьте изменения SDK и результат
`Check Telegram WebApp SDK`. Сборка сайта сверяет SHA-256 файла с `diary/telegram-web-app.sha256`.

Ролик приветствия загружается на сервер в `/opt/theabc/backend/resources/videos/welcome.mp4` перед сборкой. Docker включает его в образ. Если файла нет, бот отправляет приветственную картинку.
Для кнопки «Узнать подробнее» перед сборкой загружается `/opt/theabc/backend/resources/videos/details.mp4`.

```bash
journalctl -u theabc-autodeploy -n 50     # лог деплоя
docker compose ps                          # состояние контейнеров
docker compose logs -f bot api             # логи
```

## Партнёрские выплаты

Для выплат по номеру карты задайте `REFERRAL_PAYOUT_CARD_KEY` в `/etc/theabc/referral-payouts.env` с правами `0600`. Значение генерирует `cryptography.fernet.Fernet.generate_key()`. Файл загружается только в контейнер API. Храните резервную копию ключа отдельно от дампов БД, чтобы можно было обработать открытые заявки после восстановления.

## ЮKassa

- Оферта, тарифы и контакты доступны в раскрываемом блоке на экране входа сайта. После входа цены и порядок получения услуг есть в разделе «Подписка и баланс»: `https://abcofme.ru/?page=billing`. Контакты и реквизиты: `https://abcofme.ru/?tab=profile&page=contacts`. Оферта: `https://abcofme.ru/?tab=profile&page=offer`.
- Контакты исполнителя хранятся в `diary/src/features/legal/business.js`. Цены в разделе «Подписка и баланс» берутся из профиля (`backend/pricing.py`). При изменении тарифов обновляйте также фиксированные суммы в оферте `diary/src/features/legal/offer.js`.
- Ключи в `.env`: `ACCOUNT_ID` — shopId, `SECRET_KEY` — секретный ключ (кабинет → Интеграция → Ключи API). Тестовый магазин даёт ключ `test_…`, боевой — `live_…`.
- HTTP-уведомления (кабинет → Интеграция → HTTP-уведомления): URL `https://abcofme.ru/api/webhook/yookassa`, события `payment.succeeded` и `payment.canceled`. Перед зачислением сервер сверяет статус, сумму и валюту через API ЮKassa.
- На сайте и в мини-приложении кнопка покупки открывает форму ЮKassa в браузере. Пользователь сайта возвращается в «Подписка и баланс» по адресу из `PAYMENT_RETURN_URL` или `WEB_APP_URL`. Пользователь Telegram возвращается по ссылке `BOT_LINK?startapp=billing`, для которой у бота должно быть настроено главное мини-приложение.
- По умолчанию Premium оплачивается разово на 30 дней. После подтверждения ЮKassa проверьте в тестовом магазине согласие, напоминание, продление и отказ от списаний, затем задайте `YOOKASSA_AUTORENEW=true` для `api` и `bot`. Автопродление доступно для аккаунтов с Telegram, куда приходит напоминание минимум за сутки до первого списания. Для изменения суммы, периода или условий новой подписки обновляйте `AUTORENEW_TERMS_VERSION`.
- Проверяйте тестовый магазин на отдельном окружении с его `ACCOUNT_ID`, `SECRET_KEY` и URL HTTP-уведомлений. Боевой магазин может авторизовать запрос `GET /v3/me`, даже когда приём платежей ещё выключен (`status: disabled`).
- Исполнитель регистрирует каждый успешный платёж, включая автопродление, в «Мой налог» и передаёт сформированный чек покупателю.

## Бэкапы

`theabc-backup.timer` каждый день в 03:30 кладёт дамп в `/var/backups/theabc/` (хранится 14 дней).
Плюс бэкапы диска в панели Timeweb.

Восстановление:

```bash
gunzip -c /var/backups/theabc/db-ДАТА.sql.gz | docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```

## Если заблокировали ретранслятор

Он ничего не хранит. Новый VPS за рубежом (1 vCPU / 1 ГБ):

1. `apt install nginx ca-certificates`, сгенерировать сертификат с `subjectAltName=IP:<новый IP>`
   (команда — в истории настройки, `openssl req -x509 -newkey ec ...`), положить в `/etc/nginx/relay/`.
2. `apt install libnginx-mod-stream`. Скопировать `relay/nginx-tg-relay.conf` в `/etc/nginx/sites-enabled/`,
   `relay/nginx-stream.conf` — в `/etc/nginx/stream.conf` и добавить `include /etc/nginx/stream.conf;`
   в `nginx.conf` вне блока `http`. ufw: открыть 80 и 443.
   Установить `relay/nginx-restart.conf` в `/etc/systemd/system/nginx.service.d/restart.conf`,
   выполнить `systemctl daemon-reload` и `systemctl enable --now nginx`.
3. На московском сервере обновить `/etc/theabc/relay-ca.pem` и `TELEGRAM_API_URL` в `.env`,
   затем `docker compose up -d bot`.
4. В DNS перевести `abcofme.ru`, `www` и `app` на новый IP.

## Вход по логину и паролю

- `BROWSER_LOGIN_NAME` и `BROWSER_PASSWORD_HASH` задаются в серверном `.env`. Пароль в репозиторий и клиентский код не помещается. Хеш создаёт `backend.password_auth.hash_password`. Значение хеша в `.env` заключайте в одинарные кавычки, чтобы Docker Compose не интерпретировал символы `$`. При пустых значениях вход отключён.
- Браузерный аккаунт использует отдельный отрицательный ID `-1`, имя «Тестовый пользователь» и логотип вместо аватара; Telegram-профили используют положительные ID. Вход не привязывает аккаунты. Данные сохраняются между входами, права администратора не выдаются.
- Проверка пароля выполняется на сервере, максимум 10 попыток за 5 минут на IP. Выход завершает текущую сессию.
